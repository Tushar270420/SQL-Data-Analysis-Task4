# SQL Data Analysis — eCommerce Case Study

> **Portfolio focus:** SQL • Data Analysis • Relational Thinking • Business Analytics

## Business Problem

An eCommerce business needs to query customer and order data efficiently to answer questions about customers, high-value orders, spending behavior, and reusable analytical logic.

## Objective

Demonstrate practical SQL analysis using filtering, aggregation, joins, subqueries, views and indexing.

## Dataset

The project documentation describes a sample eCommerce dataset containing customer and order information.

## Tools

- SQL
- MySQL 8.0
- DB Fiddle for execution/testing
- GitHub

## Workflow

1. Inspect the customer and order data model.
2. Filter records using `SELECT`, `WHERE` and `ORDER BY`.
3. Aggregate spending using `GROUP BY` and `SUM`.
4. Combine related tables with joins.
5. Use subqueries to identify high-value customers.
6. Encapsulate reusable logic with views.
7. Explore indexing as a query-performance technique.
8. Validate outputs with saved query screenshots.

## Analysis Covered

The repository includes evidence for queries covering:

- All customers
- Customers from India
- Orders above a high-value threshold
- Total spending by customer
- Customer/order joins
- Customers spending above a threshold using subqueries
- A high-spender analytical view
- An indexing example

## Key Insights

The project is primarily a SQL-skills demonstration. The repository's saved query outputs show the progression from basic filtering to multi-table analysis, subqueries, views and performance-oriented indexing.

## Business Recommendations

The SQL patterns support practical business questions such as:

1. Identifying high-value customers for retention programs.
2. Filtering customer populations for targeted campaigns.
3. Monitoring large orders for operational attention.
4. Reusing customer-value logic through database views.
5. Improving query responsiveness through appropriate indexing.

## Results

The repository provides query examples plus visual evidence of their outputs, showing progression from foundational SQL to more advanced relational analysis patterns.
